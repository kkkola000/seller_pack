# Каталог товаров поставщиков

Веб-сервис для хостинга с Plesk: админ-панель для настройки источников данных
(прайсы Excel/CSV, YML-фиды — файлом или по ссылке) и публичная витрина
с объединённым каталогом, поиском, фильтрами и мобильной вёрсткой.

Без Composer и внешних библиотек — только PHP и MySQL, чтобы разворачивалось
на обычном шаред-хостинге.

---

## Возможности

**Админ-панель**

* Источники данных: Excel (.xlsx), CSV/TXT, YML-фид (XML).
* Два способа получения файла: ручная загрузка и ссылка (скачивание по расписанию).
* Гибкий маппинг:
  * для Excel/CSV — номер столбца (`1`, `2`) **или** буква (`A`, `B`, `AA`) для каждого поля;
  * для YML — названия тегов внутри `<offer>`, включая атрибуты (`@id`, `@available`).
* Обязательные поля: название, артикул, цена, остаток. Дополнительно: фото и валюта.
* Настройка разбора: сколько строк шапки пропустить, номер листа книги Excel,
  разделитель и кодировка CSV (или автоопределение), коэффициент к цене.
* Распознавание наличия: числовой остаток (`> 0` — в наличии) либо текст
  («в наличии», «под заказ» — списки значений настраиваются).
* Запуск импорта вручную (по одному источнику или все сразу) и автоматически по расписанию.
* Проверка маппинга до импорта: видно, что прочитано из файла и что попадёт в каталог.
* Список источников: поставщик, тип, способ получения, дата последнего успешного импорта,
  статус (активен / ошибка / отключен), количество товаров.
* Источник можно отредактировать, **деактивировать** (товары скрываются с витрины, данные остаются)
  или удалить полностью.
* Журнал импортов: время, длительность, сколько прочитано / импортировано / пропущено / удалено, текст ошибки.

**Витрина**

* Сетка товаров: название, цена, наличие, поставщик, фото (если есть в источнике).
* Поиск по названию и артикулу с задержкой ввода (debounce 350 мс).
* Фильтр по поставщику — множественный выбор.
* Фильтр по наличию: в наличии / под заказ / нет в наличии.
* Сортировка и сброс всех фильтров одной кнопкой.
* Подгрузка по скроллу + кнопка «Показать ещё», состояние фильтров сохраняется в адресе страницы.
* Мобильная вёрстка: карточки в одну колонку, фильтры — шторкой снизу; на десктопе фильтры сайдбаром.
* Тёмная тема по настройкам системы.

---

## Требования

* PHP 8.1 или новее, расширения: `pdo_mysql`, `mbstring`, `zip`, `xml`/`xmlreader`, `curl`, `iconv`.
* MySQL 5.7+ / MariaDB 10.3+.
* Apache с `mod_rewrite` (стандартная конфигурация Plesk) — либо nginx, см. ниже.

> Старый формат `.xls` (Excel 97–2003) не поддерживается — пересохраните прайс как `.xlsx`
> или используйте CSV.

## Установка на Plesk

### Быстрый путь — одной командой по SSH

```bash
cd /var/www/vhosts/ВАШ_ДОМЕН
git clone https://github.com/kkkola000/seller_pack.git catalog
cd catalog
./deploy/install.sh
```

Скрипт сам найдёт подходящий PHP (в том числе сборки Plesk из `/opt/plesk/php/*`),
проверит расширения и права, спросит доступы к базе и логин администратора,
создаст `config.php` со случайным токеном для планировщика, применит схему БД,
выставит права и напечатает две оставшиеся настройки для панели Plesk —
путь для корня документов и готовую команду для запланированной задачи.

Без вопросов, все параметры сразу (удобно для повторного развёртывания):

```bash
DB_NAME=catalog_db DB_USER=catalog_user DB_PASS='пароль_базы' \
ADMIN_USER=admin ADMIN_PASS='пароль_админа' SITE_NAME='Каталог Anex' \
./deploy/install.sh
```

Доступные переменные: `DB_HOST` (по умолчанию `localhost`), `DB_PORT`, `DB_NAME`,
`DB_USER`, `DB_PASS`, `SITE_NAME`, `ADMIN_USER`, `ADMIN_PASS`, `PER_PAGE`,
`TIMEZONE`, `CRON_TOKEN`, `PHP_BIN` (путь к PHP, если автоопределение промахнулось).

Повторный запуск безопасен: существующий `config.php` и уже созданный
администратор не перезаписываются.

**Базу данных создайте заранее** в Plesk: **Базы данных → Добавить базу данных.**

### Остальные команды

```bash
./deploy/update.sh              # обновить: бэкап, git pull, схема, права
./deploy/update.sh --no-backup  # то же без резервной копии
./deploy/backup.sh              # дамп базы + архив прайсов в storage/backups (хранятся 7 последних)

php bin/setup.php --check       # диагностика: PHP, расширения, права, база, таблицы
php bin/setup.php --write-config  # создать config.php из переменных окружения
php bin/setup.php               # применить схему и создать администратора
```

Пароли передавайте через переменные окружения, а не аргументами командной строки:
аргументы видны другим пользователям сервера в списке процессов.

### Что нужно сделать в панели Plesk

**1. Корень документов.** Хостинг и DNS → Параметры хостинга → Корневой каталог
документов:

```
/catalog/public
```

Это главный шаг для безопасности: наружу смотрит только папка `public`,
а `config.php`, загруженные прайсы и код приложения недоступны из интернета.
Если сменить корень документов нельзя, оставьте корнем папку проекта — в комплекте
есть `.htaccess`, который перенаправит запросы в `public/` и закроет служебные каталоги.

**2. Расписание импорта.** Инструменты и настройки → Запланированные задачи →
Добавить задачу. Точную команду с вашими путями печатает `install.sh`, обычно это:

```
Тип задачи:  Запустить команду
Команда:     /opt/plesk/php/8.2/bin/php /var/www/vhosts/ВАШ_ДОМЕН/catalog/bin/import.php --due --quiet
Расписание:  каждый час
```

Либо тип «Получить URL» с адресом `https://ВАШ_ДОМЕН/api/cron.php?token=ВАШ_CRON_TOKEN`.

Задача запускается раз в час, а импортируются только те источники, у которых
включён автоимпорт и прошёл их собственный интервал обновления.

После этого откройте `https://ВАШ_ДОМЕН/admin/` и войдите под созданным логином.

### Установка вручную (без SSH)

Если доступа к SSH нет, всё то же делается через Менеджер файлов Plesk:

1. Загрузите файлы проекта в каталог сайта.
2. Скопируйте `config.sample.php` в `config.php` и впишите доступы к базе,
   `site_name` и `cron_token` (любая случайная строка от 16 символов).
3. Выставьте права **775** на папку `storage` и вложенные `uploads`, `tmp`, `logs`.
4. Укажите корень документов `/catalog/public` (см. выше).
5. Откройте `https://ВАШ_ДОМЕН/install.php`, задайте логин и пароль администратора.
6. **Удалите файл `public/install.php`.**

## Если сайт работает на nginx

Правила из `.htaccess` для nginx не применяются. Укажите корнем документов
`/catalog/public` и добавьте в **Дополнительные директивы nginx**:

```nginx
location ~ ^/(app|db|bin|deploy|storage)/ { deny all; }
location = /config.php { deny all; }
```

## Как настроить источник

1. **Источники → + Новый источник.**
2. Название поставщика (видно на витрине), тип файла и способ получения.
3. Загрузите файл или укажите ссылку. Для ссылки можно включить автоимпорт и интервал.
4. Маппинг полей:
   * Excel/CSV — буква или номер столбца: `A` или `1`. Поле «Пропустить строк сверху» —
     обычно `1` (шапка таблицы).
   * YML — имена тегов: `name`, `vendorCode`, `price`, `count`, `picture`.
     Для атрибута оффера — `@available` или `@id`.
5. **Проверить маппинг** — покажет первые строки файла с буквами и номерами столбцов
   и результат разбора. Удобно сверять, не запуская полный импорт.
6. **Сохранить и импортировать.**

### Как определяется наличие

| Значение в колонке остатка | Результат |
|---|---|
| Число больше 0 | В наличии (с количеством) |
| `0` или пусто | Нет в наличии |
| Текст из списка «в наличии» (`да`, `есть`, `+`, `true`, …) | В наличии |
| Текст из списка «под заказ» (`под заказ`, `ожидается`, …) | Под заказ |

Списки значений настраиваются у каждого источника отдельно.

### Что происходит при повторном импорте

Товары сопоставляются по паре «источник + артикул»: существующие обновляются,
новые добавляются, а пропавшие из прайса — удаляются. Если импорт завершился
ошибкой, старые товары остаются на витрине нетронутыми.

## Структура проекта

```
app/
  Import/          чтение файлов и движок импорта
    Readers/       CsvReader, XlsxReader (zip + XMLReader), YmlReader
    ImportService  полный цикл импорта источника
    Fetcher        загрузка файла и скачивание по ссылке
    ColumnRef      «A» / «12» -> индекс столбца
    ValueParser    разбор цены, остатка, валюты
  Models/          работа с таблицами sources, products, import_runs
  Support/         конфиг, БД, авторизация, CSRF, разбор параметров витрины
  View/, Views/    рендер карточек товаров и страниц админки
public/            корень документов
  index.php        витрина
  admin/           админ-панель
  api/             products.php (поиск и подгрузка), cron.php (импорт по расписанию)
  install.php      установщик (удалить после установки)
bin/
  import.php       импорт из командной строки
  setup.php        установка и диагностика из командной строки
deploy/
  install.sh       развёртывание на сервере
  update.sh        обновление до свежей версии
  backup.sh        резервная копия базы и прайсов
db/schema.sql      схема базы
samples/           примеры прайса и фида
storage/           загруженные файлы, временные файлы, логи
```

### Импорт из командной строки

```bash
php bin/import.php --due            # только те, у кого подошло время (для cron)
php bin/import.php --all            # все активные источники
php bin/import.php --source=3       # конкретный источник
php bin/import.php --due --quiet    # без вывода в консоль
```

Код возврата: `0` — успех, `2` — часть источников с ошибкой, `1` — критическая ошибка.

## Производительность

Замеры на тестовом стенде (PHP 8.4, MariaDB 10.11):

| Операция | Результат |
|---|---|
| Импорт CSV, 20 000 строк | 1,4 с, пик памяти 4 МБ |
| Повторный импорт тех же 20 000 строк | 1,9 с |
| Импорт Excel (.xlsx), 5 000 строк | 0,6 с, пик памяти 8 МБ |
| Поиск по каталогу из 25 000 товаров | ~110 мс |

Файлы читаются потоково, товары пишутся пакетами по 300 строк, поэтому память
не зависит от размера прайса. Поиск работает через `LIKE '%…%'` — это даёт
подстроку в любом месте названия и артикула; на каталогах свыше нескольких сотен
тысяч товаров имеет смысл перейти на полнотекстовый индекс.

## Решение проблем

**«Сервис не настроен»** — нет файла `config.php`, скопируйте его из `config.sample.php`.

**«Нет прав на запись в storage/…»** — выставьте права 775 на `storage` и вложенные папки.

**«Из файла не удалось импортировать ни одного товара»** — скорее всего перепутаны столбцы
или число пропускаемых строк. Откройте «Проверить маппинг»: там видно, какие данные
в каком столбце лежат.

**Файл больше лимита загрузки** — увеличьте `upload_max_filesize` и `post_max_size`
в **Параметрах PHP** Plesk либо используйте загрузку по ссылке.

**Импорт большого прайса обрывается** — увеличьте `max_execution_time` и `memory_limit`,
либо запускайте импорт из планировщика: CLI-версия не ограничена временем выполнения.

**Кракозябры вместо русских букв в CSV** — укажите кодировку явно (Windows-1251)
в настройках источника вместо автоопределения.
